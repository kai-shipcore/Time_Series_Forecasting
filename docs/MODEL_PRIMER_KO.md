# 모델 입문

머신러닝 배경지식이 없는 독자를 위한 예측 모델 개념 소개입니다.

기술 참조는 `MODEL_KO.md`에 있습니다. 측정된 결과와 평가 절차는 `OVERVIEW_KO.md`에 있습니다.

## 1. 예측 대상

모델은 수요를 예측하지 않습니다. 각 제품의 최근 수준에 대한 **배수**를 예측합니다.

```
forecast = recent level  ×  predicted multiplier  ×  seasonal factor
```

최근 수준은 판매의 12주 평균입니다. 배수는 다음 질문에 답합니다. N주 뒤의 수요가 그 수준의 1.0배가 될지, 1.1배가 될지, 0.8배가 될지입니다.

**근거.** 아무것도 학습하지 못한 모델은 1.0을 예측하며 단순 이동평균을 그대로 재현합니다. 그 이동평균이 하한이며, 이를 **구조적 베이스라인**이라고 합니다. 하한을 넘어서는 정확도는 수준이나 계절성이 아니라 모델에 기인합니다. 이것이 가장 중요한 설계 개념입니다.

## 2. 알고리즘

LightGBM은 그래디언트 부스팅으로 구성한 결정 트리의 집합입니다.

| 개념 | 정의 |
|---|---|
| 결정 트리 | 예/아니오 질문으로 이루어진 순서도입니다. "최근 성장률이 1.2를 넘는가? 예 → 예측 시점이 5주보다 먼가? 예 → 1.15로 예측한다." 트리 하나만으로는 성능이 약합니다 |
| 그래디언트 부스팅 | 수백 개의 트리를 순차적으로 만들며, 각 트리는 앞선 트리들이 남긴 오차를 보정합니다. "부스팅"은 약한 모델을 쌓는다는 뜻이고, "그래디언트"는 각 트리가 남은 오차를 겨냥한다는 뜻입니다 |
| 조기 종료 | 따로 떼어 둔 제품 집합에서 개선이 멈추면 트리 생성을 중단하며, 이를 통해 잡음에 맞추는 것을 방지합니다 |

## 3. 피처

피처는 트리가 분기 기준으로 삼을 수 있는 하나의 열입니다. 모델에 주어지지 않은 열은 모델에게 보이지 않습니다.

모든 피처는 규모에 무관한 비율이므로, 큰 제품과 작은 제품이 같은 척도로 표현됩니다. 하나의 모델이 카탈로그 전체를 담당할 수 있는 이유가 여기에 있습니다.

| 피처 | 정의 | 신호 | 사용 모델 |
|---|---|---|---|
| `lead` | 1에서 13까지 | 예측 대상까지의 주 수입니다. 지평 길이에 따라 수요가 이동할 수 있게 합니다 | 두 모델 모두 |
| `ramp_4_12` | 4주 평균 / 12주 평균 | 제품이 가속하고 있음 | short 전용 |
| `y_last_r` | 기준 주 / 12주 평균 | 최근 위치 | 두 모델 모두 |
| `lag_1_r` | 기준 주 직전 주 / 12주 평균 | `y_last_r`와 함께 보는 단기 방향 | 두 모델 모두 |
| `elev_long` | 4주 평균 / 52주 평균 | 제품이 연간 정상 수준보다 크게 높으므로 회귀를 예상함 | long 전용 |

모델당 피처는 네 개이고, 서로 다른 피처는 다섯 개입니다. `ramp_4_12`는 "올랐으니 더 오를 것이다"로 읽히고, `elev_long`은 "한 해 전체에 비해 올랐으니 되돌아올 것이다"로 읽힙니다. 추가 lag 피처는 `FUTURE_IMPROVEMENTS_KO.md` §2의 후보이며 현재는 사용하지 않습니다.

## 4. 정확도 측정

절차와 결과는 `OVERVIEW_KO.md` §5와 §6에 있습니다.

| 개념 | 정의 |
|---|---|
| Pooled WAPE | 총 절대 오차 / 총 실제 수요입니다. 낮을수록 좋으며, 0.20은 20% 오차를 뜻합니다 |
| 10주 합계 | 채점 단위입니다. 재고는 주 단위로 따로 주문하는 것이 아니라 지평 단위로 주문하기 때문입니다 |
| 수요 가중 | 큰 제품이 더 크게 반영됩니다. 판매량이 큰 제품에서 20% 빗나가면 손실이 더 크기 때문입니다 |
| As-of 규칙 | 어떤 컷오프에서든 모델은 그 시점에 존재하던 정보만 사용할 수 있습니다. 각 제품의 분류는 컷오프 시점 기준으로 다시 계산합니다 |
| 개발 구간 | 서로 다른 계절에 속한 과거 10주 구간 세 개입니다. 어떤 결과도 한 기간에만 의존하지 않게 합니다 |
| 격리된 구간 | 개발 중에는 들여다보지 않은 네 번째 구간이며, 최종 테스트로 한 번만 사용합니다 |
| 부트스트랩 | 제품 목록을 무작위로 수천 번 다시 뽑아 정확도 격차가 얼마나 움직이는지 측정합니다. 그 움직임보다 훨씬 큰 격차는 실제 격차입니다 |
| 사전 등록 | 각 실험 전에 성공 기준을 기록합니다. 성공과 기각을 모두 기록으로 남깁니다 |

## 5. 설계 결정

**모델링 전 계절성 제거.** 수요를 계절 계수로 나누고, 모델은 평탄해진 시계열을 학습하며, 마지막에 계절성을 다시 곱합니다. 이렇게 하면 "12월은 크다"를 제품마다 다시 학습할 필요가 없어집니다. 2년치 데이터로는 그런 학습을 뒷받침할 수 없습니다.

**이력 길이 기준 세그먼트 구분.** short는 판매 이력이 약 50주 미만이고, long은 50주 이상입니다. 신생 제품은 상승세를 타고, 자리 잡은 제품은 안정적이며 평균으로 회귀합니다.

**하나가 아닌 두 개의 모델.** short 제품은 카탈로그 전체로 학습한 모델을 사용하여 다른 제품에서 빌려 온 패턴의 이점을 얻습니다. long 제품은 `elev_long`을 가진 전용 모델을 사용합니다.

주의: 하나의 공유 모델 안에서 long 제품을 겨냥한 변경은 모두 short 제품을 악화시켰습니다. 모든 제품이 같은 트리를 공유하기 때문입니다. 두 모델은 다시 합치지 않습니다.

## 6. 버전 이력

| 버전 | 결과 |
|---|---|
| v0에서 v3 | 성장 드리프트 보정, 궤적 피처, 계절성 일관성을 차례로 쌓아 올렸습니다. 연휴 이후 자리 잡은 제품을 과대 예측한 점을 제외하면 성능이 우수했습니다 |
| v4, v5, v7, v8 | 해당 셀을 세그먼트 처리 문제로 보고 다루었습니다. 세그먼트 플래그, 세그먼트별 계절 계수, 세그먼트별 학습 가중치, 모델 분리를 시도했습니다. 각각 자리 잡은 제품은 개선했지만 신생 제품은 악화시켰습니다 |
| v6, v9 | 결함을 찾아냈습니다. 연휴 상승분이 수요가 이미 떨어진 12월 말에 적용되고 있었습니다. 구간을 11월 말에서 12월 중순으로 바로잡자 상당한 개선이 있었습니다 |
| v10 | 하이퍼파라미터 튜닝으로는 개선이 없었고, 설정이 원인일 가능성이 배제되었습니다 |
| v11 | 연휴 이후의 과대 예측은 하락 국면에 상승세를 외삽한 결과였고, 전환점을 감지할 수 있는 피처가 없었습니다. `elev_long`이 그 신호를 제공합니다. short 제품에 영향을 줄 수 없도록 전용 long 모델에 배치했습니다 |
| v12에서 v18 | 모두 기각되었으며, 판매 이력만으로 도달할 수 있는 한계를 확인했습니다 |

요약하면, 세그먼트 배정이나 튜닝의 문제가 아니라 잘못 지정된 계절 달력과 부재한 전환점 신호의 문제였습니다.

## 용어집

| 용어 | 의미 |
|---|---|
| WAPE | 가중 절대 백분율 오차이며, 정확도 지표입니다. 낮을수록 좋습니다 |
| Pooled | 나누기 전에 제품 전체를 합산하므로 큰 제품이 더 크게 반영됩니다 |
| Cutoff | 백테스트의 "오늘"이며, 모델은 그 이후의 정보를 전혀 사용할 수 없습니다 |
| Segment | short(신생) 제품과 long(자리 잡은) 제품의 구분입니다 |
| Structural baseline | 이동평균 하한이며, 배수 1.0을 예측하면 이것이 재현됩니다 |
| Prototype | 은퇴한 통계 시스템(statsforecast)이며, 정확도 기준선입니다 |
| V1 | 이 프로젝트 이전에 사용하던 스프레드시트 수식입니다 |
| Deseasonalise | 모델링 전에 계절 계수를 나누고 이후에 다시 곱하는 처리입니다 |
| Feature | 트리가 질문을 던질 수 있는 열입니다 |
| Elevation | 연간 수준 대비 4주 수준이며, 연휴 셀 문제를 해결한 피처입니다 |
| Bootstrap | 실제 정확도 격차와 우연을 구분하는 재표집 검정입니다 |
| Pre-registration | 실험을 실행하기 전에 성공 기준을 적어 두는 것입니다 |
| Quarantined test | 따로 떼어 둔 구간이며, 개발 중에는 쓰지 않고 한 번만 사용합니다 |
