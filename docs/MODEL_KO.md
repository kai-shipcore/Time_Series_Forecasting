# 모델

운영 모델의 아키텍처와 설계 근거입니다. pandas, 교차 검증, 그래디언트 부스팅 트리에 대한 지식을 전제하며, `MODEL_PRIMER_KO.md`는 같은 내용을 그러한 전제 없이 다룹니다. 문제 정의, 결과, 평가 프로토콜은 `OVERVIEW_KO.md`에 있습니다.

`ML_FORECAST_DESIGN.md`가 전체 기록입니다. §4는 근거를 포함한 모든 결정을, §6은 버전 로그를 담고 있습니다. 이 문서가 덜 구체적인 부분에서는 해당 문서가 우선합니다.

**지배 규칙.** 한 번에 하나의 가설만 다루며, `src/ml/evaluate.py`를 통해 세 개의 개발 구간에서 평가하고, `OVERVIEW_KO.md` §5의 채택 기준으로 판정하며, 채택 여부와 무관하게 결정 로그에 기록합니다. 통과 기준은 먼저 기록합니다.

## 1. 모델링 관점의 문제

규칙적으로 판매되는 340개 SKU에 대해 SKU별 주간 수량 수요를 13주까지 예측합니다. 이력은 대략 2년이며, 판매 기록 외에 유용한 공변량은 없습니다.

| 사실 | 결과 |
|---|---|
| 2년은 연간 계절 이벤트당 관측이 두 번이라는 뜻이며, 데이터로부터 계절성을 학습하기에는 부족합니다 | LightGBM에 달력 피처를 주어 계절성을 스스로 학습하게 하는 M5 대회 방식은 배제됩니다. 여기서 시도한 결과, 관측했던 특정 월을 그대로 재현했고 연휴 이후 저점을 +123% 과대 예측했습니다 (설계 문서 §4.9) |
| 대부분의 SKU가 신규입니다. 예측 가능한 340개 SKU 중 247개가 이력 50주 미만이므로 SKU별 적합에는 활용할 자료가 거의 없습니다 | 이는 **전역** 모델을 뒷받침합니다. 전체 SKU를 함께 학습한 하나의 모델은 한 SKU에서 학습한 패턴을 다른 SKU로 전이시킵니다. 이 SKU 간 전이가 SKU별 프로토타입 대비 핵심적인 구조적 이점이며 측정 가능합니다. short 전용 모델은 이를 잃고 성능이 더 나빠집니다 (v8) |

설계는 M5가 아니라 M4를 따릅니다. 규모와 계절성은 구조적으로 부과하고, LightGBM은 데이터가 뒷받침하는 잔차 동학에 국한됩니다.

## 2. 아키텍처

### 2.1 목표값은 수준이 아니라 비율

```
y_target / (trailing 12-week mean of that SKU's history at the cutoff)
```

분모는 **앵커 수준**이며, `src/ml/model.py:264`의 `denom`입니다. 모든 비율 피처가 이 값으로 나뉩니다.

**근거.** 아무것도 학습하지 못한 모델은 1.0을 예측하여 구조적 베이스라인을 재현하므로, 측정된 모든 변동은 시험 중인 피처에 귀속됩니다.

### 2.2 왕복 처리로서의 계절성

| 요소 | 세부 내용 |
|---|---|
| 왕복 처리 | 수작업으로 설정한 월별 배수를 적합 전에 이력에서 나누어 제거한 뒤, 예측값에 다시 곱합니다. 모델은 달력을 전혀 보지 않습니다 |
| 범위 | **long SKU에만 적용됩니다.** short SKU에는 계절 조정이 적용되지 않습니다. 측정 결과에 따른 것이며 (설계 문서 §4.10, §4.17), `src/ml/model.py:176`의 `adjusted_series(weekly, long_uids)`가 구현합니다 |
| 배수 | `src/ml/seasonal.py` |
| 연휴 오버라이드 | `ML_HOLIDAY_START = (11, 20)`과 `ML_HOLIDAY_END = (12, 15)` 사이의 월별 계수를 `ML_HOLIDAY_MULTIPLIER = 1.26`으로 대체합니다 (`config.py:141-143`). ML의 종료일인 12월 15일은 프로토타입의 12월 31일과 다릅니다. 프로모션이 11월 말부터 12월 중순까지 진행되므로 v9에서 이를 옮겼습니다 |
| 블렌드 | v11에서 `ML_SEASONAL_BLEND`는 `"off"`입니다. `"holiday"`와 `"full"` 블렌드는 각각 v16과 v15로 시도되어 기각되었습니다 |

### 2.3 직접 예측 방식의 다중 지평

하나의 모델이 지평을 입력 피처(`lead`)로 사용하여 13개 지평 전부를 다룹니다. 재귀가 없으므로 1주차의 오차가 13주차까지 누적되지 않습니다.

### 2.4 현재 모델, v11

모델은 두 개입니다. 공유 모델 하나로는 두 세그먼트를 모두 감당할 수 없었습니다.

| 세그먼트 | 학습 대상 | 피처 |
|---|---|---|
| smooth/short | 전체 smooth SKU | `lead`, `ramp_4_12`, `y_last_r`, `lag_1_r` |
| smooth/long | long SKU만 | `lead`, `y_last_r`, `lag_1_r`, `elev_long` |

`src/ml/model.py:40` (`FEATURES_V1`)과 `:53` (`FEATURES_V11_LONG`)에 정의되어 있습니다.

long 모델은 지속적인 과대 예측을 유발하던 성장 피처 `ramp_4_12`를 제거하고 `elev_long`을 추가합니다. 최근 수준 비율은 두 모델 모두에 남아 있으므로 점진적 성장은 계속 추적됩니다.

### 2.5 피처 정의

`build_matrix` (`src/ml/model.py:191-291`)에서 계산됩니다. `roll4`, `roll12`, `roll52`는 각각 해당 주 수에 대한 후행 평균입니다.

| 피처 | 산식 | 신호 |
|---|---|---|
| `lead` | 1 에서 13 | 이 행이 얼마나 앞을 예측하는지를 나타냅니다. 하나의 모델이 모든 지평을 담당하게 합니다 |
| `ramp_4_12` | `roll4 / denom` | 직전 한 달을 직전 분기와 대비합니다. 상승 중인 SKU를 감지합니다. short 모델 전용 |
| `y_last_r` | `y_feat / denom` | 앵커 주를 수준과 대비합니다. 최근 위치 |
| `lag_1_r` | `shift(1) / denom` | 앵커 직전 주를 수준과 대비합니다. `y_last_r`과 함께 단기 방향을 나타냅니다 |
| `elev_long` | `roll4 / roll52` | 4주를 해당 SKU의 연간 수준과 대비합니다. 값이 높으면 과열 상태이므로 회귀를 예상합니다. long 모델 전용 |

`elev_long`은 52개 행(`min_periods=52`)을 필요로 하며, 이력이 1년 미만이면 계산할 수 없고, 없을 때는 1.0으로 중립화됩니다.

참고: short/long 경계가 50주에 있는 이유는 `elev_long`이 그것을 요구하기 때문입니다.

### 2.6 모델을 분리한 이유

세그먼트 지시 변수(v4)와 세그먼트별 표본 가중(v7)은 모두 한 가지 이유로 실패했습니다. 공유된 트리가 long SKU를 위해 가한 변경을 short SKU로 옮기기 때문입니다. 분리하면 공유 트리가 사라집니다. short SKU는 세그먼트 간 전이를 위해 공유 모델을 유지하고, long SKU에는 그것이 필요하지 않습니다.

### 2.7 하이퍼파라미터

`src/ml/model.py:350-353`에 있으며 거의 기본값입니다.

```python
n_estimators=3000,          # cap; early stopping picks the real count
learning_rate=0.05,
num_leaves=31,
min_child_samples=200,
```

조기 종료는 내부 검증 분할을 기준으로 동작합니다. 튜닝은 v10에서, 그리고 하이브리드 아키텍처에서 v18로 다시 시도되었으며 두 번 모두 기각되었습니다.

## 3. 세그먼트 분류

`src/profile.py`가 매주 계산하여 `data/processed/sku_profiles.csv`에 기록합니다. SKU를 예측할지 여부와 어느 모델이 담당할지를 결정합니다.

### 3.1 버킷

`classify()` (`src/profile.py:216`)에 독립적인 필터가 두 개 있습니다. 둘 중 하나라도 해당하면 그 SKU는 **intermittent**이며, 그렇지 않으면 smooth입니다.

| 검사 | 상수 | 값 |
|---|---|---|
| 전체 주의 30% 이상이 0 | `ZERO_PCT_INTERMITTENT` | 0.30 |
| 주간 평균 수요가 컷오프 미만 | `MEAN_INTERMITTENT_CUTOFF` | 3.0 |

### 3.2 동적 오버라이드

후행 `RECENT_WEEKS = 13` 구간을 기준으로 조정됩니다.

| 오버라이드 | 조건 | 위치 |
|---|---|---|
| 승격 (intermittent에서 smooth로) | 최근 0 비율이 `RECENT_ZERO_PCT_UPGRADE = 0.20` 미만이고 **동시에** 최근 평균이 `RECENT_MEAN_UPGRADE = 3.0` 이상 | `src/profile.py:238-245` |
| 강등 (smooth에서 intermittent로) | 최근 평균이 `RECENT_MEAN_DOWNGRADE = 2.0` 미만 | |

**근거.** 기준값이 같으면 임계값 부근의 SKU가 매주 뒤집히고, 뒤집힐 때마다 해당 예측이 제거되거나 복원됩니다. 3.0과 2.0 사이의 간격이 히스테리시스입니다.

### 3.3 이력 길이

`src/profile.py:76`의 `_history_length(active_weeks)`입니다.

| 레이블 | 임계값 | 의미 |
|---|---|---|
| `short` | 50주 미만 | long 모델의 입력에 쓰기에는 이력이 너무 적음 |
| `medium` | 50 에서 104 | `elev_long`에 충분함 |
| `full` | 104 이상 | 계절 주기 2회 이상 |

모델과 관련된 모든 곳에서 `medium`과 `full`은 "long"으로 통합됩니다.

주의: 알려진 off-by-one 문제이며 그대로 두었습니다. `active_weeks`는 `(data_end - train_start).days / 7`로 계산되는 기간이므로, 50개 행으로 이루어진 구간이 49주로 집계되고 medium 레이블을 받으려면 SKU에 **51**개 행이 필요합니다. `dataset.asof_history_length`가 동일한 기간을 계산하므로 평가와 운영이 일관되게 1주씩 늦습니다. 이를 변경하면 양쪽 모두에서 SKU가 경계를 넘어 이동하고, 최종 테스트의 수치를 포함해 기록된 모든 수치의 기준이 다시 설정됩니다. 자세한 내용은 `FUTURE_IMPROVEMENTS_KO.md` §3에 있습니다.

### 3.4 승격된 SKU와 `_smooth_onset`

승격된 SKU의 `train_start`는 smooth 동작이 시작되는 지점으로 설정되어야 합니다. `_smooth_onset` (`src/profile.py:134`)은 최근 구간에서 거꾸로 거슬러 올라가 승격 검사를 여전히 충족하는 가장 긴 기간을 찾습니다. 변경에 앞서 해당 함수의 docstring이 우선합니다.

주의: 2026-08-11 이전에 기록된 수치는 그 이후에 기록된 수치와 비교할 수 없습니다. 해당 일자에 수정된 결함으로 인해, 당시 smooth 집합의 41%에 해당하는 승격 SKU 190개가 모든 평가 수치에서 제외되어 있었습니다. 이전 수치에는 측정에 사용된 snapshot이 함께 표기되어 있습니다.

## 4. 실험 실행

```bash
.venv/bin/pip install -r requirements.txt     # exact pins; results compare at the 3rd decimal
.venv/bin/python scripts/ml_XX_your_experiment.py
```

현재 `.venv`에는 `lightgbm`이 설치되어 있지 않습니다. 모든 `ml_*` 스크립트 실행에 앞서 requirements 설치가 필요합니다.

실험은 `scripts/ml_*.py`에 있으며, `src/ml/`에서 가져다 쓰되 거기에 추가하지는 않습니다. 각 실험은 후보를 세 개의 개발 구간에 대해 실행하고 세그먼트별 표를 출력합니다.

1. 실행 전에 가설과 통과 기준을 버전 로그에 기록하십시오.
2. 세 개의 개발 구간에서만 실행하고, 최종 테스트 구간에서는 절대 실행하지 마십시오.
3. 요약하기 전에 세그먼트별 원시 출력을 제시하십시오.
4. 기각을 포함하여 결과를 결정 로그에 기록하십시오.

모델 버전은 태그가 붙은 커밋(`model/v-base` 이후)이며, 각각 해당 버전의 트리를 담고 그 결과는 커밋 메시지에 기록되어 있습니다.

**최종 테스트 구간은 격리되어 있습니다.** `scripts/ml_41_final_test.py`만이 이 구간을 다룹니다. 이 스크립트는 변경 사항이 남은 트리를 거부하고, 기존 결과의 덮어쓰기를 거부하며, 사전 조건을 먼저 확인합니다.

이미 실행되었습니다. 설계 문서 §4.35에 결과가 기록되어 있고 `OVERVIEW_KO.md` §6이 이를 요약합니다. 다시 실행하지 않습니다.

## 6. 측정 한계

전체 목록은 `OVERVIEW_KO.md` §7에 있습니다. 그중 세 가지가 모델링 작업과 관련됩니다.

- **인용된 수치는 낡습니다.** 본문에 서술된 수치는 아무것도 실패하지 않은 채로 시효를 잃을 수 있으며, 실제로 세 차례 발생했습니다. 계산된 값이 선호됩니다
- **승격된 SKU는 백테스트로 검증할 수 없고 전향적으로만 검증할 수 있습니다.** 승격된 SKU는 구조상, 이전 컷오프에서라면 자격을 얻지 못했을 이력을 갖고 있습니다
- **V1 비교는 2026-08-13까지 as-of off-by-one 오류를 안고 있었으며**, 모델에 유리한 방향으로 어긋나 있었습니다

## 7. 퇴역한 예측기
